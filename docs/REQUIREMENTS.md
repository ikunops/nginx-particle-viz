# nginx 光子流 · 需求规格

> 这份文档描述**要做什么、为什么这样设计**，不描述「照着某份代码改」。
> 目标是：任何人（或 AI）只读这份文档，就能从零实现出同等效果，不需要接触任何参考实现。
>
> 版本：v1.0 · 2026-11

---

## 1. 一句话需求

把 nginx 的实时运行状态，画成一幅「数据流过网关」的动态图：左边是各个监听端口的请求，
汇入中央的处理核心，再分发到右边的各个上游后端。**屏幕上每个数字都必须来自真实采集，
不允许有随机数或估算值。**

---

## 2. 数据层（先做这个，UI 才有意义）

### 2.1 必须采集的三类数据

| # | 数据 | 来源 | 为什么不能用别的 |
|---|---|---|---|
| 1 | 每台上游的 rps / 字节数 / 响应时间 / 错误率 | access.log 里的 `$upstream_addr`、`$upstream_status`、`$upstream_response_time`、`$body_bytes_sent` | `stub_status` 只有全局总量，无法拆到单台后端 |
| 2 | 监听端口 → 上游 的对应关系 | 解析 `nginx -T` 的 `server{}` / `location{}` / `proxy_pass` / `upstream{}` | 这是唯一能知道「哪个入口代理到哪几台」的地方 |
| 3 | 累计请求数 / 转发数 / 错误数 | 日志计数 | 仪表盘和状态栏需要 |

### 2.2 日志格式要求

必须新增一个独立 `log_format`，**不要修改现有格式**（可能有其他地方在解析）：

```
字段顺序（用 | 分隔）：
0  $time_iso8601
1  $server_port          ← 用于按入口分组
2  $remote_addr
3  $request
4  $status
5  $body_bytes_sent
6  $request_time
7  $upstream_addr        ← 核心：请求去了哪台后端（决定性字段）
8  $upstream_status
9  $upstream_response_time
10 $upstream_cache_status
11 $http_user_agent
```

**踩过的坑**：这个格式后来加过字段，解析器按固定下标取值，字段一变就整体错位，
`$upstream_addr` 读成空，所有聚合恒为 0。**解析时必须先确认字段数量，
并在字段变动时能发现（比如日志长度不符合预期就丢弃并计数）。**

### 2.3 `nginx -T` 解析规则

需要从输出中提取：

```
upstream 名字 { server host:port [weight=N] [max_fails=N] [fail_timeout=N]; ... }
server { listen PORT; location 路径 { proxy_pass http://目标; } }
```

- 一个 server 可能有多个 listen，全部记录
- 一个 server 可能有多个 location，**每个 location 的 proxy_pass 都要看**
- `proxy_pass` 指向 `upstream 名字` 时，展开为该 upstream 的全部成员
- `proxy_pass` 直接写 `host:port` 时，就是个单点后端
- **必须过滤掉观测端口自身**（本页面的端口、采集器端口），否则它们会被当成业务流量画出来

**为什么不写死**：配置会变，写死的列表永远和实际不符。

### 2.4 容量分母（五层降级）

「负载到 500/1000 就显示一半」需要分母。但 nginx 只有你配了才有上限，
所以要自动探测，探测到哪层用哪层，**并在界面上标注用的是哪一种**：

| 优先级 | 配置来源 | 速率条分母 | 并发条分母 |
|---|---|---|---|
| 1 | `limit_req zone=... rate=Nr/s` | N（换算成每秒） | — |
| 2 | `limit_conn zone N` | — | N |
| 3 | `upstream { server x max_conns=N; }` | — | N |
| 4 | `worker_connections N` × `worker_processes` | — | N × 进程数 |
| 5 | 都没有 | 观测到的峰值 rps | 观测到的峰值并发 |

**关键：速率和并发必须用不同的分母。**
`worker_connections` 是连接数上限，拿它当 rps 的分母会得到无意义的极小值
（5 rps ÷ 4096 = 0.1%，条永远不动）。

### 2.5 输出接口

```
GET  /api/topology     一次完整快照
GET  /api/stream       SSE，每秒推送一次增量
POST /api/config/ack   前端应用完新配置后回报，用于清除变更提示
```

`/api/topology` 返回结构：

```jsonc
{
  "nodes": [
    {"id":"listen:80", "kind":"listen", "label":":80", "rps": 0.0},
    {"id":"up:127.0.0.1:8088", "kind":"upstream", "label":"127.0.0.1:8088",
     "rps": 2.5, "bw": 745.0, "latency": 0.48, "errRate": 0.0, "state": "ok"}
  ],
  "links": [
    {"source":"listen:80", "target":"up:127.0.0.1:8088", "kind":"proxy"}
  ],
  "rate": { "inbound": 5.0, "proxied": 5.0, "ratio": 1.0 },
  "counters": { "requests": 219583, "proxied": 219577, "errors": 0,
                "bytes": 66167731, "active": 0.0, "uptime": 1165.9 },

}
```

### 2.6 配置变更检测

- 对 `nginx -T` **全文**算 SHA1（不要只哈希过滤后的行——两套不同的配置可能过滤后相同）
- 哈希变化 → `reloadNeeded = true`，累计 `changed` 次数
- 把上次哈希持久化到文件，服务重启后不误判为「变更」
- 前端应用完成后 `POST /api/config/ack` 清除标记

**踩过的坑**：`nginx -s reload` 有时不会重新打开新的日志文件。
表现为配置生效、页面返回 200、但 access_log 一直不写入。**必须 `systemctl restart nginx`。**

## 4. 中央视觉：黑洞 + 吸积盘

这是整个页面的主体，占中央约 60% 宽度。

### 4.1 形状要求

- **中心是一个黑洞**：纯黑圆形，边缘有一圈极细的亮环（光子环），环外渐隐
- **外围是吸积盘**：大量极细的曲线缠绕、盘旋，形成星云般的密度感
- **整体气质**：柔和、连续、没有折角。**绝对不允许出现「折线」「铁丝」「爪子抓球」的观感**

### 4.2 线条的正确画法（技术要点）

**这是最容易做错的地方，务必按此实现：**

```
每一条线 = 两段三次贝塞尔曲线拼接

段1：起点 → 中继点
  控制点1 = (起点x + dx*0.50, 起点y)    ← 与起点同 y，保证「出发水平」
  控制点2 = (中继点x - dx*0.50, 中继点y) ← 与终点同 y，保证「到达水平」

段2：中继点 → 落点
  控制点1 = (中继点x + dx*0.42, 中继点y) ← 「出发水平」
  控制点2 = 沿盘缘切线方向退后       ← 「切向到达」
```

**为什么必须这样**：段1 到达时切线水平，段2 出发时切线也水平，**接缝处天然 C1 连续，
不需要任何平滑处理**。这是线条柔和的根本原因。

**常见错误（都踩过）**：

| 错误做法 | 后果 |
|---|---|
| 用 catmull-rom 串多个控制点 | 控制点位置稍有不齐，切线就乱，看起来像钢丝 |
| 在路径中间加「远点」，先外扩再收回 | 接缝处出现 **153° 发夹弯**，整条线折了 |
| 用多段独立贝塞尔 `concat` 拼接 | 接缝切向不一致，出现明显折角 |
| 后处理 `smoothPath` 抹平 | 抹不掉控制点本身造成的折返，只是把折角变钝 |

**判定标准**：沿路径逐点算相邻段的转角，**最大值应 < 10°，平均值 < 1°**。
如果出现单点 > 100°，就是发夹弯，必须回去查控制点。

### 4.3 落点分布（避免「排线」「梳子」）

每个入口分配一**段弧**，不是**一个点**。该入口的所有线在这一段弧内均匀铺开。

```
弧的分配（屏幕 y 向下，3 点钟方向 = 0°）：
  左半球（入口）: 120° ~ 240°   （对应时钟 11点 → 7点）
  右半球（上游）: +58° ~ -58°   （对应时钟 1点 → 5点）
```

**踩过的坑**：早期用了 `-118° ~ +118°` 作为左半球，这个区间跨过 0°，
而 `x = cx + R*cos(a)` 在 0° 处是**最右端**。结果 4 条线里 3 条落到了右半球。

**左半球的数学定义是 `cos(a) < 0`，即 `90° < a < 270°`。**

### 4.4 随机化（避免呆板）

三个维度都要有确定性随机（同一 seed 每次结果相同）：

```
入射角   ±6°
起点偏移 ±8px（在卡片高度内）
落点半径 基准的 ±10%
```

**只随机这些位置，不随机「方向」**——线必须始终单调向内，不能有「先外后内」。

### 4.5 密度

每个入口 **约 40 条线**。太少显得空，太多看不清单根。

### 4.6 颜色

**每个入口一个色相，该入口的所有线继承同一个颜色。** 这样整片扇面读起来是彩色丝带，
而不是一片同色的细线。上游侧同理。

建议色板（区分度好，在深色背景上都够亮）：

```
#8cc8ff  蓝    #8fe3b9  绿    #f2b872  橙    #ff9f8c  珊瑚
#b9a6ff  紫    #72d4d0  青    #d6df7c  黄绿  #f0a6c4  粉
```

### 4.7 描边方式

- **用 `source-over`，不要用 `lighter`**。多个通道在总线附近重叠时，`lighter` 会把
  重叠区叠到饱和，孤立的线反而看不见，整体呈一片乱亮条。
- 每条线描三遍做光带感：**粗淡底（1.8px / alpha 0.07）+ 中层（1.0px / 0.16）+ 亮芯（0.6px / 0.34）**
- 不要用渐变对象（每帧几百个会卡）

### 4.8 光点（流动感）

- 沿曲线移动的小亮段，**不是圆点**，是**短而粗的彩色横段**（长度约为曲线参数 1.2%，宽度是基础线的 2.2 倍）
- 头部加一个 1.8px 的白色小方块
- 速度越靠近核心越快：`t += dt * v * (0.62 + t*1.1)`
- 两端淡入淡出，避免突然出现/消失

### 4.9 淡出（融入吸积盘）

线的末端要**在盘内**淡出，不能在盘外凭空消失：

```
盘内的径向亮度包络（参考值）：
  内圈几乎平台，约 0.42R 处降到一半，外圈保留 0.26 的底
淡出区间：0.86R → 0.52R
```

在盘外淡出 = 线「凭空消失」；在盘内淡出 = 线「化进雾气」。

### 4.10 中继带

左右各一条竖直的窄带，所有线在带上收束再展开：

- 位置：球外侧约 1.3R
- 高度：覆盖画面 25%~83%（左）/ 15%~86%（右）
- 画法：极暗底板 + 每 8 格一个长刻度 + 竖排标签（`INGRESS` / `EGRESS`）
- **不参与任何指标编码**，纯粹是分组边界

## 5. 两个阶段

只有两个阶段，循环播放。

| 阶段 | 名称 | nginx 含义 | 时长 |
|---|---|---|---|
| 1 | 吸积 INGEST | 请求进入 nginx，写入 access.log | 3.0 ~ 16.0 秒 |
| 2 | 转发 COLLAPSE | 匹配 location 后 proxy_pass 到上游 | 1.2 ~ 6.0 秒 |

**时长必须由真实速率决定，不能写死：**

```
时长 = hi + (lo - hi) * min(1, ln(1+rps) / ln(1+40))

速率高 → 时长短（动画跑得快）
速率 0 → 时长 = hi（慢下来）
```

**为什么**：写死时长的话，不管有没有流量动画都在跑，那是「动画」不是「实时」。

### 5.1 循环交界处必须平滑（重要）

collapse 结束时和 ingest 开始时，这几个视觉量会突变，必须处理：

| 量 | collapse 结束 | ingest 原始起点 | 处理方式 |
|---|---|---|---|
| 环半径系数 ring | 1.00 | 0.00 | ingest 头 35% 从 1 缓出到 0 |
| 能量 energy | 1.20 | 0.45 | 从 1.20 平滑过渡到自然爬升曲线 |
| 黑洞尺度 holeK | 1.12 | 1.00 | 头 35% 从 1.12 缓出到 1.00 |

```js
// ingest 阶段
const settle = clamp(p / 0.35, 0, 1);
const ease2 = 1 - Math.pow(1 - settle, 3);   // 缓出

ring   = (1 - ease2) * 1.00;
holeK  = 1 + (1 - ease2) * 0.12;
energy = (1 - ease2) * 1.20 + ease2 * (0.45 + 0.4 * p);
```

**不做这个处理的话**，每轮结束会看到画面「啪」地弹回，非常突兀。

### 5.2 循环时不要重建卡片 DOM

每轮重建卡片会闪一下。用内容签名比对，只有拓扑真的变了才重建：

```js
const sig = parts.map(q => q.n + '|' + q.task).join(';');
if (lastSig !== sig) { lastSig = sig; rebuildCards(); }
```

## 6. 左侧卡片（每个 listen 端口一张）

```
┌───────────────────────────────────────┐
│ in1                              A01  │  ← 端口名 + 序号，背景是该入口的颜色
├───────────────────────────────────────┤
│ 请求 ▬▬▬▬▬▬ 0.22   并发 ▬▬▬ 0.05     │  ← 两根条 + 数值
│ :18080  2 个上游  均值 ▬ 4.3 rps IDLE │  ← 端口 / 上游数 / 均值 / 状态
│ ▏▎▍▌▋▊▉▊▋▌▍▎▏                        │  ← 迷你柱状图（历史负载）
└───────────────────────────────────────┘
```

| 字段 | 含义 | 数据来源 |
|---|---|---|
| 请求（条） | 该入口 rps ÷ **速率分母** | `capacity.rate.value` |
| 并发（条） | 该入口承担的上游数 ÷ **连接分母** | `capacity.conn.value` |
| 均值 | 最近 30 个采样的滑动平均，附绝对值 | 滑动窗口 |
| 端口 | listen 端口号 | `nginx -T` |
| N 个上游 | 该端口代理到几台后端 | topology links |
| BUSY / IDLE | 是否有流量 | 实时 rps |
| 迷你柱状图 | 最近 32 个负载采样 | 滑动窗口 |

**悬停卡片显示分母来源**，例如「请求条分母: 观测峰值 85.0 rps / 并发条分母: worker_connections 1024 x 4」。

**重要**：`均值` 的标签必须放在**不会被更新的容器里**。
如果放在会被 `card.task.textContent = ...` 每帧覆写的元素里，标签会消失。

## 8. 底部四个面板

| 编号 | 名称 | 内容 |
|---|---|---|
| 05 | 事件流 | 实时日志（阶段切换、请求处理），带时间戳 |
| 06 | 连接负载 | 每个入口的横向条 + 队列数 |
| 07 | 实时配置 | **真实 nginx.conf 逐字符打字机打印** |
| 08 | 网关遥测 | 累计请求 / 并发连接 / 已转发 / 错误响应 |

### 8.1 07 面板的特殊要求

- **内容必须是真实 nginx 配置**，不是编造的示例代码
- **必须逐字符打印**（打字机效果），不是整行出现
- **必须有行号**（用 CSS 计数器或 `data-n` 属性 + `::before`）
- **必须有语法高亮**：指令名（紫）/ 参数值（青）/ 数字（绿）/ 注释（灰）
- 打完后从头循环
- **配置变更时从头重新打**

**踩过的坑**：用 `setInterval` 每 400ms 插入一整行 → 没有打字感，而且到达 DOM 上限后
就停住了。正确做法是推进一个字符队列，每帧消费几个字符。

### 8.2 04 响应记录

每轮转发结束时记一条：

```
16:10  R1   4 个上游 · 5 rps   0.6ms
```

## 9. 配置热更新（必须做到不打断）

### 9.1 用户期望

```
配置改了 → 提示条出现 → 等当前这轮跑完 → 自动应用 → 提示条消失
         （不需要点按钮，不需要刷新页面，视角不变）
```

### 9.2 实现要点

**① 不立刻重建，等到循环边界**

半途重建会让环、能量、黑洞尺寸瞬间跳到新状态，视觉上就是「啪」一下。
重建必须发生在 `吸积 → 转发 → 下一轮吸积` 的边界。

**② 旧光点必须能飞完**

重建会换掉曲线数组。如果光点按索引读取新数组，会读到错误的曲线。
**必须做双缓冲**：

```
保留两代曲线数组：gen[0] / gen[1]
光点出生时记录代号 g
渲染时按 g 取对应那一代的数组
旧一代没有光点引用后释放
```

**③ 视角必须保持**

重建卡片会改变 DOM 高度，可能触发布局重算导致相机重置。
重建前保存相机状态（yaw / pitch / zoom），重建后恢复。

**④ 提示条不能一直挂着**

`reloadNeeded` 是服务端的锁存位。应用完成后必须 `POST /api/config/ack` 清除，
否则下次加载又弹出来。

## 10. 视觉硬约束（不可违反）

这些是反复沟通后定下的，**不是审美偏好，是需求**：

| # | 约束 | 原因 |
|---|---|---|
| 1 | 线宽**不编码任何指标** | 试过，视觉上无法分辨，且让线看起来像钢丝 |
| 2 | 光段宽度**不编码带宽** | 带宽以数字形式显示在侧栏 |
| 3 | 延迟**不驱动路径弯曲** | 弯曲只由几何决定，否则路径不可预测 |
| 4 | 线数**固定**，与通道数、流量无关 | 流量用亮度/光点密度表达 |
| 5 | 亮度**只编码占比** | 单一维度，避免歧义 |
| 6 | 故障**必须更亮**，不是更暗 | 反直觉的错误：曾把 fail 状态乘 0.55 变暗，导致黑线 |
| 7 | **不用虚线** | 用户明确拒绝 |
| 8 | **不加光晕/发光** | 用户明确拒绝 |
| 9 | 循环交界**必须平滑**（见 5.1） | 硬跳会产生「弹回」感 |
| 10 | 曲线**不能有折角**（最大转角 < 10°） | 折角 = 钢丝感，最核心的视觉要求 |

## 13. 验收标准

## 附：调试方法

**测转角**（判断有没有折角）

```js
for (let i = 2; i < path.n - 1; i++) {
  const ax = path.x[i] - path.x[i-2], ay = path.y[i] - path.y[i-2];
  const bx = path.x[i+1] - path.x[i-1], by = path.y[i+1] - path.y[i-1];
  const d = (ax*bx + ay*by) / (Math.hypot(ax,ay) * Math.hypot(bx,by));
  const angle = Math.acos(Math.max(-1, Math.min(1, d))) * 180 / Math.PI;
  // angle > 20 就要查
}
```

**测落点半球**（判断有没有跑错边）

```js
const ang = Math.atan2((cy - endY) / 0.86, endX - cx) * 180 / Math.PI;
// 左半球应该 90 < |ang| < 270（即 120~240）
```

**测循环连续性**（判断有没有跳变）

连续采样 `ring / energy / holeK`，跨越 `collapse → ingest` 边界，
数值必须是渐变的，不能有单帧跳变。
